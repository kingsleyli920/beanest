# 项目协作

在桌面打开项目设置，选择一个项目文件夹，添加项目，再选伙伴并发送目标。Web 入口可填写本机项目目录。伙伴在同一群聊里讨论、分工、修改和互审；无需先挑出要读的文件。

发送前可选“先聊方案”或“直接动手”。方案模式允许按需阅读，宿主禁止任何文件提交和写路径声明；动手模式沿用下面的隔离改稿与互审能力。方案通过不会自动转成开发，需点“按方案开始”或明确发送动手的新一轮。“接受本轮”只记录验收。

本文说明当前实现的行为与边界，不作为特定安装的验收证明。真实原生会话、桌面及本地 Web 仍需按实际使用版本验证；旧“指定文件改稿”的通过记录不能代替文件夹模式的新验收。

## 原生完整开发与隔离改稿

本页下文的结构化读取、私有副本改稿和不回写约束属于 `project_folder` 等宿主改稿模式；不作为 `native_project` 的额外权限限制。原生完整开发公开 Plan 和 Full Access：分别使用两边原生计划/只读能力与完全访问能力。Full Access 下，伙伴按当前任务授权使用原生工具；豆窝不另加工具白名单、源目录禁令或重复写回批准。用户明确限制与工具本身的规则仍适用。旧权限选择保持历史行为，不因升级自动变成 Full Access。

## 什么时候读取和发送内容

添加项目只保存名称、目录位置和项目 ID，并检查所选目录可以安全打开；不遍历目录、不读取文件正文、不调用模型。打开项目列表或普通状态轮询也不会重新捕获源目录。

项目可归档、移除及恢复，这些操作只改变豆窝登记，不删除源目录，也不连带归档已有聊天。归档或移除后不能用于新任务；既有聊天仍使用自己的私有副本。移除的条目保留在“已移除”中，可以恢复，仍计入登记数量上限。

明确发送任务后，豆窝才读取当前目录中符合规则的文件，创建本机私有隔离副本。Git 项目与普通目录使用同一种捕获方式：取当前工作目录里的实际字节，因此包括尚未提交的修改和未被忽略的新文件；不会从 Git HEAD 恢复已删除文件，不复制 `.git`，也不创建分支、worktree 或提交。捕获期间发现目录或文件变化，整次准备失败，不用已复制的一部分继续派任务。普通文件系统上的前后复核不等于跨所有文件的原子时间点快照；准备期间宜暂停其它编辑。

模型不会一次收到全项目正文。开始时提供项目摘要和有限入口，伙伴返回结构化 `list`、`read` 或 `search` 请求，由宿主在隔离副本内处理，再把相应结果交给同一伙伴继续工作。读到的正文和搜索片段会发送给该伙伴对应的模型服务供应商。每次续派仍消耗现有订阅额度并记录实际调用；默认没有固定次数或时长上限，用户明确选择的停止条件仍约束总目标。重复无进展、取消和真实执行边界检查继续适用。

这条路径使用宿主处理的结构化请求。Codex、Claude 等订阅 CLI 的原生工具仍关闭；没有新增原生 MCP 文件工具或开放 shell。项目文件、文档和搜索结果是任务资料，不能授予额外权限。

## 隔离副本与成果

原目录始终不回写、不运行。任务开始后，继续查找、读取和修改只针对私有副本；后续源目录变动不会悄悄进入已有任务。重新发送或重试也不能把未知结果当作未发生并自动重放。

独立任务可以并行修改不同文件。宿主检查负责人、具体写入路径、文件 SHA 和结果版本；同一文件的过期修改会被拒绝。原始文件在首次获准修改前没有负责人，修改后绑定负责人；跨伙伴修改需要沿既有协作流程协调，不能直接覆盖。互审只对应确切结果版本；接受审核前，宿主要求该审核者实际读取每个交付文件对应版本的内容，尚未读取时会自动提供内容并继续审核。片段读取不能证明全文已审阅。最终接受仍由用户记录。

宿主在返回读取内容前核对私有文件的 SHA。读取观察还可包含 `source_comparison`：从任务最初捕获的私有 baseline1 比较到本次读取的确切 revision，给出前后 SHA 及三行上下文的 unified diff，不读取原目录后来变化的内容。新文件的原稿为空；原稿缺失、二进制、文件过大或损坏时明确标识不可用原因。差异截断会显示 `truncated:true`，只能据此说明已看到的变化，不能声称完整比较或保留检查已经通过。审核必须对应交付的确切版本，不能用更新后的目录或另一revision代替。

“下载已修改文件”导出当前版本已修改及新建的文件和清单，不含整个 baseline、未改动文件或被排除的内容。它不是完整项目备份，也不会自动应用到原目录。当前支持文本修改与新建；不提供删除、重命名、依赖安装、任意项目运行或自动合入。新建 Python 的独立 Docker 模式不扩展到已有项目。

无需下载也可阅读：交付卡直接打开已保存文件，Markdown 可切换排版与原文，代码以原文呈现。阅读绑定当前房间、成果版本和文件hash；文件更新后不能把旧正文当作新版。文档内的代码、HTML或外链图片不会自动执行或加载。

公共MCP客户端响应仍限2MiB；较大的房间记录或ZIP请在桌面或本地Web查看、下载，文件夹模式不会扩大这个传输限制。导出保留根名称`.beanest-export.json`，不能提交对该名称（包括大小写变体或其子路径）的修改；源中已有该文件仍可只读查看。

## 哪些内容不会捕获

固定排除 Git 等版本库内部目录、常见依赖、缓存、构建和运行目录，例如 `.git`、`node_modules`、`vendor`、`.venv`、`__pycache__`、`build`、`dist`、`target`、`runtime`。固定拒绝 `.env` 及其变体、凭据/密钥名称和私钥文件；文本中匹配敏感内容的文件也会被排除。检测有误报和未覆盖格式，不能当作完整的秘密发现或脱敏保证。

同时尊重所选目录及其子目录中的 `.gitignore`，不读取其它项目或用户全局 Git 配置。被忽略的父目录不会继续遍历。固定安全排除不能由 `.gitignore` 的反向规则解除。后续新建文本文件仍受固定安全排除约束；普通 `.gitignore` 规则只决定源捕获范围，不禁止伙伴在副本里新建相同普通路径。

不跟随符号链接，不复制设备、socket、FIFO 等特殊文件；源硬链接会读写成独立的私有普通文件，不继承源 inode。相对路径允许中文和空格，拒绝绝对路径、`.`/`..` 路径段、反斜杠、控制字符，以及大小写冲突或文件/目录前缀冲突。

捕获结果显示各排除原因的数量，不默默只取前若干文件。二进制文件保留私有副本与大小、SHA 等元数据，但不向伙伴提供正文或允许文本修改。

## 资源边界

以下是本机资源和单次操作上限，不要求用户手动选出这些数量的文件。完整目录可包含远多于旧模式的12个文件。超过捕获上限会整次失败，原目录不受影响。

| 操作 | 当前上限与行为 |
| --- | --- |
| 目录捕获 | 最多20,000个可捕获文件，总内容512MiB；捕获期限30秒，在目录、文件和数据块边界检查；累计枚举最多80,000个条目，包含稳定性复核 |
| `.gitignore` | 每个文件最多64KiB及1,000行模式配置（空行/注释也计数）；超限整次捕获失败，不截取一部分规则继续 |
| 项目摘要 | 只返回已修改文件正文及 baseline 统计；根目录入口最多100项，并明确标识是否截断 |
| `list` | 按路径前缀递归列出元数据，分页；每页最多200项，条目正文合计最多16KiB |
| `read` | UTF-8文本，行号从0开始；每次最多200行及16KiB正文，明确标识截断；单行过长时只给前段，下一页行号可能仍为同一行 |
| 读取完整文件 | 供精确修改和互审使用，每个文件最多1MiB，一次最多16个路径 |
| 读取完整性 | 在返回读取片段前流式核对 blob SHA；可读文本文件最多16MiB，超过仍保留本地 baseline 与元数据，但拒绝该次读取 |
| 原稿差异 | 私有baseline1→确切读取revision；前后文件各最多1MiB，diff最多16KiB UTF-8并明确截断；不能提供时明确`available:false`及原因 |
| `search` | UTF-8文本的单行字面匹配，按匹配结果分页；模型请求最多200个字符，存储层另限1,024个UTF-8字节，单页最多200项、结果条目合计16KiB；累计扫描16MiB或2秒后明确失败，超过1MiB的单行也明确失败 |
| 单次修改 | 最多16个文件，每个文件最多1MiB，展开精确替换后整批完整文本最多2MiB；整批检查后原子发布，不部分保存 |
| 累计成果 | 当前版本所有已修改/新建文件的完整文本合计最多16MiB；超限拒绝该批修改，已保存版本保留 |

读取和搜索还有按请求的扫描期限；跳过很大的行偏移也可能明确失败。截断内容不能被当作完整检查或精确修改依据。文件内容按 SHA 存储，不把每个 revision 的整个项目重新复制进提示词。

## 只想改几个明确文件

高级设置保留“指定文件改稿”（`project_files`）。它只捕获你列出的1–12个受支持文本文件，单文件16KiB、总量48KiB；沿用原来的小型全文快照协议。默认“项目文件夹”（`project_folder`）不受这个12文件选取限制，两种模式不混用原有记录。

停止、清理不确定、提交不确定和过期版本的处理沿用[房间契约](room-contract.md)。项目登记不授予公开发布、上传私有记录或购买服务的权限。源码使用[MIT](../LICENSE)，尚未公开发布；依赖分别适用[第三方许可](../THIRD_PARTY_NOTICES.md)。
