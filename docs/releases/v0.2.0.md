# Beanest v0.2.0 · early preview

[English](#english) · [简体中文](#简体中文)

## English

This is the first public release of Beanest. It is an early preview for one person on their own Mac. Expect rough edges. Bug reports are the most useful thing you can send.

### What has been used for real

These have run with real agents on the maintainer's machine, not only in tests:

- One task with Claude Code, Codex, and Kimi Code working together on an existing project: they split the work into shared tasks, claimed them, and reviewed each other's deliveries in one chat.
- Plan (read-only discussion) and Build (changes in a development copy of the project).
- When a partner ran out of quota, it left the task and its work went to another partner. With one partner left, deliveries were marked "Self-check only".
- When every partner ran out of quota, the task waited and continued once quota came back.
- Recovering a native call that was cut off, after checking cleanup and the private copy.
- English and Chinese interface.

### Checked for this release

On a clean clone of `main` on macOS:

- The README install steps work: `python3 -m venv .venv`, `pip install -e .`, and the optional `.[bridge]`.
- `python -m local_agent_coordinator.room_server` starts and prints a loopback URL. The page loads.
- An MCP client connects through `room_mcp --connection runtime/rooms/connection.json` and lists 14 tools.
- `npm --prefix desktop ci` and `npm --prefix desktop run build:local` build the desktop app.
- Interface tests (473) and desktop tests pass. The Python suite passes on CI with Python 3.12, 3.13 and 3.14. Python 3.11 is not supported: some cancellation tests fail on it.

### Known limits

- macOS only for the desktop app. It is built from source and depends on the checkout and its `.venv`. There is no signed or notarized installer.
- Single user, local only. Do not expose the service to a network.
- A development copy is not a sandbox. With Full Access, an agent can run commands, use the network, and reach other files your account can read.
- Kimi Code support is the least mature: in the maintainer's use, Kimi calls failed more often than Claude Code or Codex calls.
- Automatically continuing a stop that "Continue" would fix is new in this release. It has worked in real use, for example after the app was quit mid-call, but has not been watched over many days.
- Tests use provider substitutes. They do not prove compatibility with every provider version or that long runs never break.

### Requirements

Python 3.12+, Node.js 22.12+ for the desktop app, and at least one of Claude Code, Codex, or Kimi Code installed and signed in.

## 简体中文

这是豆窝第一次公开发布，属于早期预览版，面向在自己 Mac 上单人使用的场景。会有不少粗糙的地方，最有用的是问题反馈。

### 已经真实用过的功能

下面这些在维护者本机接真实 Agent 跑过，不只是测试：

- Claude Code、Codex、Kimi Code 一起处理同一个已有项目：拆成共享任务、认领、互相审核交付，全程在一条聊天里。
- “方案”（只读讨论）和“动手”（在项目开发副本里改）。
- 某个伙伴额度用完时退出任务，手上的活交给别的伙伴；只剩一位时交付标为“仅自检”。
- 所有伙伴额度都用完时，任务等额度恢复后接着做。
- 原生调用中途断掉后，核对清理和私有副本，再恢复。
- 中英文界面。

### 这次发布前核对过的

在 macOS 上用 `main` 的全新克隆：

- README 的安装步骤能跑通：`python3 -m venv .venv`、`pip install -e .`、可选的 `.[bridge]`。
- `python -m local_agent_coordinator.room_server` 能启动并打印本机地址，页面能打开。
- MCP 客户端通过 `room_mcp --connection runtime/rooms/connection.json` 能连上，列出 14 个工具。
- `npm --prefix desktop ci` 和 `npm --prefix desktop run build:local` 能构建出桌面应用。
- 界面测试（473 项）和桌面端测试通过；Python 测试在 CI 上用 Python 3.12、3.13 和 3.14 跑。不支持 Python 3.11，部分取消相关的测试在 3.11 上会失败。

### 已知限制

- 桌面版只支持 macOS，从源码构建，依赖源码目录和 `.venv`，没有签名或公证的安装包。
- 单用户、只在本机用，不要把服务暴露到网络上。
- 开发副本不是沙箱。Full Access 下，Agent 可以执行命令、联网，也能访问你账号有权限的其他文件。
- Kimi Code 的支持最不成熟：维护者实际使用中，Kimi 调用失败的比例明显高于 Claude Code 和 Codex。
- “点继续就能解决的停下会自动继续”是这一版新加的。真实使用中已经生效过，比如调用中途退出 App 之后，但还没有经过连续多天的观察。
- 测试用的是供应商替身，不能证明兼容所有供应商版本，也不能证明长时间运行不出错。

### 运行要求

Python 3.12+；桌面版需要 Node.js 22.12+；至少安装并登录 Claude Code、Codex、Kimi Code 中的一个。
